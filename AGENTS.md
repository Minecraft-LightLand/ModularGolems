# AGENTS.md

Modular Golems: a Tinker-style golem assembly/upgrade mod for Minecraft 1.21.1 (NeoForge), part of xkmc's L2 mod family (L2Complements, L2Library, etc.). Author: lcy0x1.

## Build & run

- Toolchain: Gradle 8.8 wrapper, Java 21, NeoForge ModDev plugin, Parchment mappings. `org.gradle.daemon=false`, so every invocation is slow.
- `./gradlew build` — builds jar + sources jar into `build/libs/`.
- `./gradlew runClient` / `runServer` — dev runtime in `run/` (gitignored). This is the real way to validate changes; there are no meaningful unit tests.
- `./gradlew runData` — regenerates everything under `src/generated/resources` (committed to git). Runs the data provider (ModDev args in build.gradle:55).
- Publish tasks (`publishCurseForge`, modrinth via Minotaur) read tokens from `secrets.properties` (gitignored) and changelog from `changelog.txt`. Publishing is not part of normal dev workflow.

## Dependencies (important gotcha)

- L2 libs (l2serial, l2core, l2library, l2complements, l2weaponry, ...) resolve from `mavenLocal()` + flatDir `libs/` (vendored jars). Pinned versions live in `gradle.properties`.
- This repo sits in `mods_l2/` alongside the sibling L2 projects. When an L2 dependency changes, its sibling repo must be built and installed (`./gradlew publishToMavenLocal`) or its jar copied into `libs/` before this mod picks it up.
- If a dep is missing, first check `libs/` and `~/.m2` before assuming a network issue.

## Architecture

- Entry: `init/ModularGolems.java` (`@Mod` class) — registers registrate (`GolemItems`, `GolemTypes`, `GolemModifiers`, `GolemMiscs`, `GolemMiscEntities`), the L2Serial packet handler, and the `PARTS` / `MATERIALS` `ConfigTypeEntry`s.
- Stats are registered as `GolemTypes.STAT_*` entries (e.g. `STAT_HEALTH`, `STAT_ATTACK`, `STAT_WEIGHT`, `STAT_REGEN`, `STAT_KBRES`, `STAT_SWEEP`); modifiers registered in `GolemModifiers` are namespaced `modulargolems:<name>`.
- Golem content lives in `content/` (entities under `content/entity/`, items under `content/item/`, modifiers under `content/modifier/`).
- Mixins are in `mixin/`; every new mixin must also be added to `src/main/resources/modulargolems.mixins.json` (client-only ones under `"client"`, `defaultRequire: 1`).
- Event listeners live in `events/`.

## Mod integrations (compat)

- Integrations live in `compat/materials/<mod>/` as a `*Dispatch extends ModDispatch` class, and `compat/<mod>/` for non-material integrations (jei, curio, maid, backpack, jade, ...).
- Each dispatch is gated by `if (ModList.get().isLoaded(...))` in `CompatManager.register()` (compat/materials/common/CompatManager.java). Add new integrations there; dispatches also provide datagen (`genLang`, `getDataGen`) and a client proxy.
- Compat code must compile against the optional mod's classes as `implementation` deps (many come from cursemaven; see build.gradle dependencies).

## Data-driven config & generated files

- Golem materials and part stats are data-driven JSON under `data/<ns>/modulargolems_config/materials|parts/` (e.g. `data/modulargolems/modulargolems_config/materials/vanilla.json`).
- These are GENERATED from `init/data/MGConfigGen.java` (via L2Core `ConfigDataProvider`) and each compat dispatch's gen. Never hand-edit files under `src/generated/resources`; edit the provider, then run `./gradlew runData`.
- `src/main/resources` is also a datagen input (`--existing`), so hand-authored assets (textures, patchouli books under `assets/modulargolems/patchouli_books/golem_guide/`, compat assets under e.g. `assets/twilightforest/`) stay there.
- Lang: en_us is generated by Registrate into `src/generated/resources/assets/modulargolems/lang/en_us.json`; edits go through `MGLangData` (init/data) or dispatch `genLang`.

## Conventions

- Branch names are per MC version: `1.20`, `1.21`, active work `dev/1.21` (this branch, MC 1.21.1 / NeoForge 21.1.197), `dev/1.21-skin`, and newer `26.1`. Match target MC/NeoForge of the branch.
- Version is `mod_version` in `gradle.properties`; the top block of `changelog.txt` is the changelog for that version. Release commits are titled with the version (e.g. "3.1.42").
- `src/test/java/organize/*` (ResourceOrganizer, GUIGenerator, LangFileOrganizer) are standalone dev utilities for shuffling lang/resource files, not gradle tests.
